# Forms → monday.com plan

**Status:** agreed in principle (2026-11-13). Application form front end built as a placeholder; handler, database
and staff page not built yet.
**Goal:** stop LeaderFlow staff retyping form submissions into monday.com by hand, and make the forms safer and more
reliable than Ninja Forms.

## Decisions so far

| # | Decision | Date |

## The problem today

Applications come in through Ninja Forms on the WordPress site and arrive as emails. Someone on staff reads each email
and types the details into monday.com by hand. That's slow, error-prone, and grows with every application.

The audit (01, section 4) also found:
- the application's résumé upload no longer renders
- its Email and Phone fields are built as the wrong field types
- it has no Turnstile spam check
- it stores applicants' personal data on a WordPress install that had spam pages planted on it

## monday's API is not a paid extra

monday's API is included on **every plan, including Free**. The Free, Basic and Standard plans allow
[1,000 API calls a day](https://developer.monday.com/api-reference/docs/rate-limits), and one submission uses 1 to 3.
A paid add-on is only needed if an account goes over its limit
([API rate limits](https://support.monday.com/hc/en-us/articles/26471164460690-API-Rate-Limits)). Phase 2 costs build
time, not a monday subscription.

## How it fits together

Everything is built around **one Cloudflare D1 database** (plus **R2** storage for résumé files). The email, the staff
page, the spreadsheet and the Phase 2 monday sync all read the same rows, so they never disagree.

```
Applicant submits a form
        │
        ▼
Form handler (Cloudflare Pages Function: /api/contact, /api/flowcilitator, /api/application)
        ├── checks it: Turnstile, honeypot, every field again, applications open?
        ├── saves the answers ──────► D1 database  (one row per submission)
        ├── saves the résumé PDF ───► R2 storage   (private files; applications only)
        ├── emails staff a clean copy (and, optionally, the applicant a confirmation)
        └── Phase 2 only: creates the item on the monday board

Staff go to leaderflow.org/admin/
        │
   Cloudflare Access login (one-time code sent to approved staff emails)
        │
        ▼
Staff page: reads D1, links to R2
   • list of submissions, with counts of new ones
   • "Download new" CSV for monday     → reads D1, marks those rows as downloaded
   • open a résumé                     → fetches the file from R2
   • delete a submission               → removes the D1 row and its R2 file
   • Phase 2: rows that failed to reach monday, with a Retry button
```

### Forms covered

| Form | Page | Handler | Status |
|---|---|---|---|
| Contact ("Start a discussion") | Home, Connect | `/api/contact` | Front end done |
| Become a Flowcilitator inquiry | Become a Flowcilitator | `/api/flowcilitator` | Front end done |
| Development Program application | Application Form → Apply | `/api/application` | Front end built as a placeholder (see below) |

**The application form front end** is its own step-by-step page, `application-form/apply/`, opened by "Start your
application" on the Application Form page, and is generated by `tools/application-form/build.py`. It shows one
section at a time, has a review step at the end, and any section can be opened from the section list. It has seven sections, and its fields, questions and word limits match the live
2026 form. Applicants get:
- live word counters
- a PDF résumé upload, up to 5 MB
- answers saved on their device as they type
- section progress ticks

The ethnicity options and the commitment wording are placeholders until Janiece confirms them. Preview it while
applications are closed with `?preview=open`.

### What's in the database (D1)

One `submissions` table:

| Column | Holds |
|---|---|
| `id` | Unique ID |
| `form` | `contact`, `flowcilitator` or `application` |
| `received_at` | When it arrived |
| `email`, `name` | Kept as their own columns, for lists and duplicate checks |
| `data` | Every answer, stored as JSON, so changing a question never needs a database change |
| `resume_key` | Where the résumé is in R2 (applications only) |
| `duplicate_of` | Set if the same email already applied in this cycle |
| `exported_at` | When it was included in a CSV download (empty = new) |
| `monday_item_id`, `synced_at`, `sync_error` | Phase 2 only |

## Phase 1: saved, emailed, monday-ready export

### What happens when someone submits

1. **The visitor presses Submit.** The browser has already checked the form, so they see plain-English errors before
   anything is sent.
2. **The handler checks it's genuine and complete:**
   - the Cloudflare **Turnstile** spam check, plus the hidden honeypot field
   - **every field again on the server**: required fields, email, phone, ZIP code, word limits, allowed choices, all six
     commitments ticked. Bots that skip the page and post straight to the handler are still caught.
   - **Applications only:** applications must be open. Outside the open dates it refuses, even if someone uses the
     `?preview=open` link.
   - **Applications only:** the résumé must really be a PDF (the file contents are checked, not just the name) and no
     larger than 5 MB.
3. **It saves first:** the answers go into D1, and the résumé into a private R2 bucket. If saving fails, the applicant is
   told to try again, so nothing is lost silently.
4. **It emails staff a clean copy:**
   - a fixed subject, like `Application: Jane Doe (Seattle)` or `Flowcilitator inquiry: Jane Doe (Firm X)`
   - every answer labelled, always in the same order
   - Reply-To set to the applicant
   - résumés aren't attached; the email links to the staff page, so personal files don't spread across inboxes

   If the email fails, the submission is still on the staff page.
5. **Optional: an email to the applicant**, confirming receipt with a copy of their answers. To be confirmed with
   LeaderFlow.
6. **Duplicates:** if the same email already applied this cycle, the new row is flagged for staff, not dropped.

### The staff page (`/admin/`)

A small **read-only** page, not the question-editing dashboard. Behind a Cloudflare Access login (free for up to 50
users), it lets staff:
- see all submissions per form, with a count of new ones
- click **Download new** to get the monday CSV (those rows are then marked downloaded), or **Download all** as a backup
- open a résumé
- delete a submission (removes the row and its résumé file)

Staff cannot change the forms here.

### What staff do each week

1. Go to `leaderflow.org/admin/` and enter the one-time code that's emailed to them.
2. Click **Download new applications**.
3. In monday, on the board, choose **New Item ▾ → Import Items**. Choose the file, check the column mapping, and import
   ([monday's guide](https://support.monday.com/hc/en-us/articles/360000219209-Import-files-from-Excel)). Picking
   **email** as the unique column lets monday spot people who are already on the board.

That's about two minutes a week instead of retyping every application.

### Making the import clean

- **Item name:** the first column, for example `Jane Doe`.
- **Matching headers:** column headers are named exactly like the board's columns. monday may still ask staff to confirm
  the mapping each time
  ([community thread](https://community.monday.com/t/how-to-import-csv-to-existing-board-without-manually-map-columns-every-time/43689)).
- **Résumé:** monday's import can't attach files, so a **Résumé** column holds a link to the file on the staff page.
- **Dates:** written as `YYYY-MM-DD`.
- **Status and dropdown values:** spelled exactly like the board's labels. A label that doesn't match creates a new
  label.
- **Multi-choice answers** (Flowcilitator "Which sessions?"): it isn't documented how one cell holds several dropdown
  values. Test it on a copy of the board, and fall back to a plain text column.
- **Accented names:** the file is UTF-8 with a BOM, so names like "Martínez" survive Excel. The page can produce
  `.xlsx` if the importer dislikes CSV.

### Privacy and housekeeping

- **Private storage:** the database and résumé files are never public. Only logged-in staff reach them, through the
  staff page.
- **Automatic deletion:** submissions and résumés are deleted after a period LeaderFlow chooses (suggested 12
  months).
- **Logs:** no applicant data in logs. Demographic answers are optional, and only used in anonymised reporting.

### Cost to run

- **Cloudflare free tiers** cover everything at LeaderFlow's volume:
  - Pages Functions
  - D1
  - R2 (10 GB free)
  - Turnstile
  - Access (up to 50 users)
- **Sending email** is the one extra service. Cloudflare's own email sending needs the domain's DNS on Cloudflare, which
  won't happen until the pre-launch DNS move. Until then, use **Resend** (free tier: 3,000 emails a month, 100 a day).
  It needs a couple of DNS records at GoDaddy, which the Domains Only delegate access allows.

### Build steps

1. Create the D1 database and `submissions` table and the R2 bucket, and bind them to the Pages project.
2. Write the handlers in the repo's `functions/` folder (next to `site/`, not inside it):
   - `functions/api/contact.js`
   - `functions/api/flowcilitator.js`
   - `functions/api/application.js`
   - shared code: validation, Turnstile, saving, R2 upload, email, open/closed dates
3. Connect the forms: set each form's `data-endpoint`, and add the Turnstile site key.
4. Set up Resend: verify the sending domain at GoDaddy, and store the API key as a Pages secret.
5. Build `/admin/`: the list, the two downloads, résumé viewing, delete, and the CSV export.
6. Protect `/admin/*` with Cloudflare Access, and add the staff emails.
7. Add automatic deletion (a small scheduled Cloudflare Worker).
8. Test end to end:
   - submit each form, including a fake non-PDF résumé and an application while closed
   - check the emails
   - download the CSV and import it into a **test copy** of the monday board
   - check every column, the résumé link and the dropdowns
9. Write a one-page "how to import" guide for staff, with screenshots.

**Rough effort:**
- contact and Flowcilitator forms, staff page and export: 1.5 to 2 days
- application handler with résumé storage and the open/closed check: 1 to 1.5 more days (the front end is already
  built)

## Phase 2: straight into monday

### What changes

Phase 1 stays the same, plus one step after saving:

- **The handler creates the item on the board** through monday's API (`create_item`, with the column values filled
  in). It records the monday item ID on the row.
- **Duplicates:** before creating an item, it looks up the applicant's email on the board. If they're already there, it
  adds an update to the existing item, if LeaderFlow wants that.
- **If monday is down or rejects it**, the submission is still saved and emailed, and the row is marked "not synced".
  The staff page shows these with a **Retry** button. The handler also retries unsynced rows on the next submission,
  and the scheduled Worker retries them daily.

Staff do nothing: new submissions appear on the board within a second or two. The CSV download stays as a backup.

### Setup

1. **API token:** made in monday under Developers → My access tokens. A token acts as the person who made it, so use a
   shared "website" monday user if possible. The token is stored as a Pages secret, never in the code.
2. **Board and column IDs:** looked up once and stored in the handler's config, so renaming a column in monday doesn't
   break anything. Deleting a column or changing its type does, and shows up as "not synced".
3. **Testing:** test on a copy of the board, then switch to the real one.

### Cost and effort

- **monday:** no extra charge (1 to 3 API calls per submission, against 1,000 a day).
- **Cloudflare:** still free.
- **Effort:** about 1 day, including testing.

### Needed from LeaderFlow for Phase 2

- [ ] A monday API token, ideally from a shared website user, sent securely.
- [ ] Permission to create a test copy of the board.
- [ ] A decision on duplicates: update the existing item, or create a new one.

## Later phase (after Phase 2): question-editing dashboard

A staff dashboard for editing the application questions, options and word limits without a developer. The questions
would move from `build.py` into the same D1 database, and the form would be built from them. It has its own scope
and price, to be planned when the time comes.

**Two different admin pages; don't mix them up:**
- **Phase 1 staff page (`/admin/`):** read-only. View and download submissions, open résumés, delete.
- **Later-phase dashboard:** edits the application questions.

## Why this is better than Ninja Forms

| | Ninja Forms (today) | Our forms (Phase 1) |
|---|---|---|
| **Lost submissions** | Depends on an email plugin; failures can go unnoticed | Saved first, then emailed; always on the staff page |
| **Résumés** | Upload currently broken; the uploads add-on usually saves to WordPress's public uploads folder | Private R2 storage, staff-only; file really checked as a PDF |
| **Personal data** | In a WordPress install that was compromised | Private database, staff login, automatic deletion |
| **Spam** | Honeypot only on the application | Turnstile and honeypot, plus server checks |
| **Rules** | Email/phone fields mis-built; dates not enforced | Every field checked twice; late applications refused; duplicates flagged |
| **Applicants** | One long page; no saving | Sections with progress, word counters, answers saved as they type |
| **Into monday** | Retyped by hand | One spreadsheet import (Phase 1), automatic (Phase 2) |
| **Upkeep and cost** | WordPress hosting, plugin licences, updates that can break things | Cloudflare free tiers; no plugins |
| **Editing questions** | Staff can do it themselves | Developer for now; dashboard in a later phase |

## Not recommended

- **monday "Email to board":** only the subject and body come through
  ([how it works](https://support.monday.com/hc/en-us/articles/115005339645-Email-to-board)). Staff would still copy
  every field by hand.
- **Zapier / Make:** they work, but add a monthly fee for something we can do for free.
- **monday WorkForms, Tally, Google Forms:** considered for the application. We chose our own form so everything goes
  through one handler and one export, under LeaderFlow's branding.
